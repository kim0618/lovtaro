# 러브타로 꿈해몽 사전 작성 스킬

`lovtaro` 프로젝트의 `/dream` 섹션에 **퀄리티가 브랜드를 결정하는** 꿈해몽 글 1편을 작성한다. 얇거나 AI스러운 글, 멋대로 지어낸 해몽은 절대 발행하지 않는다. 기준 미달이면 기준까지 다시 쓴다.

## 존재 이유 / 포지셔닝

꿈해몽은 사주·운세 사이트와 블로그가 빽빽한 레드오션이다. 범용 꿈해몽으로 정면 경쟁하지 않는다. 우리 니치는 **"연애+꿈 롱테일"** - "전 애인 꿈 재회", "좋아하는 사람 꿈 의미"처럼 운세 사이트가 약하고 연애 타로 브랜드가 강한 각도다. 신규 도메인이 일반 대형 키워드(이빨·똥 등)로 상위 진입은 어렵다는 전제 위에서, 연애가 지배적 해석인 꿈을 우선한다.

## 편수 원칙 (절대)

- 사용자가 명시하지 않으면 **하루 1편.** 2편 이상 금지.
- 기준 미달이면 리라이트 허용. 편수 채우려고 얇게 발행하지 않는다. 기준 미달이면 발행을 미뤄도 OK.
- verify 통과 전 commit·배포 금지. 배포는 사용자가 직접(빌드까지만).

## 핵심 작성 원칙: 근거 위 재해석 (3겹)

1. **전통 해몽(근거)** - 그 꿈의 일반적/전통적 통념을 먼저 파악(필요 시 WebSearch). 검색 유저가 기대하는 표준 해석에서 벗어나지 않는다. 멋대로 발명 금지.
2. **러브타로 연애 각도(브랜드)** - 표준 해석 위에 "이 꿈이 연애·관계에 주는 신호"를 얹는다.
3. **가능성의 언어(톤)** - 카드 사전과 동일한 화법. "~인 경우가 많아요", "~신호일 수 있어요". 점쟁이 톤이 아니라 마음을 비추는 거울 톤.

연애 직결도가 낮은 범용 꿈(이빨·똥·물)은 표준 해몽을 메인으로 깔고 연애는 보조 1섹션만. 억지로 연애를 메인에 욱여넣지 않는다. 무리하면 그 주제는 스킵하고 큐에서 연애 직결 주제를 당겨온다.

2. **전통 해몽 근거 확인** - 그 꿈의 표준 통념을 파악. 불확실하면 `WebSearch`로 확인. (예: 뱀=재물·이성운, 이빨=가족·구설, 태몽=새 생명·변화)

   ### 🛑 검색 AI 요약을 근거로 승격 금지 (2026-08-10 신설, 절대)

   **`WebSearch` 결과에 딸려오는 AI 요약문을 전통 해몽 근거로 쓰지 않는다.** 요약은 출처를 붙여 그럴듯한 문장을 만들지만, **그 문장이 원문에 없는 경우가 실제로 발생했다.**

   *배경 (2026-08-10 `military-dream` 사고)*: "면회 가는 꿈" 검색 시 AI 요약이 *"전역자가 후임 면회를 가는 꿈은 부정적 영향이 크지 않으나 마음이 약간 무거워질 수 있다"* 를 **나무위키 출처로** 제시했다. 이를 "전통 해몽에서도 큰 흉조로 보지 않는다"로 옮겨 적었는데, 나무위키 '군대 꿈' 문서 원문을 받아 세어보니 **'면회' 0회·'해몽' 0회·'길몽' 0회**였고 애초에 해몽서가 아니라 재입대 악몽이라는 문화현상 문서였다. 같은 글에서 "군인=규율·질서·의무"(실제 해몽전서는 "이익과 영달 및 목표달성"), "강제 징집=원치 않는 것을 떠안음"(실제는 "갖거나 누리고 싶은 감정") 등 **AI 요약 문구가 그대로 전통 근거로 승격된 것이 5건**이었다. 전통 근거층 1/5로 사이트 최저를 기록하고 전면 재작성했다.

   **필수 절차**:
   - **해몽 사전 원문을 2곳 이상 직접 열어 표제어를 확인한다.** `WebFetch`로 페이지를 열고 해당 항목이 실제로 있는지 본다. 검색 결과 목록·요약만 보고 판단하지 않는다.
   - **원문에 그 항목이 없으면 "근거 없음"이다.** 비슷한 항목으로 유추해 채우지 않는다. 갈래를 삭제하거나, 검증된 축 위에 얹는 자체 재해석임을 본문에 명시한다.
   - **"자료가 없다"고 선언하기 전에도 사전을 연다.** 위 사고에서 "전역 꿈은 전통 자료가 뚜렷하지 않다"고 정직성 표시를 달았는데, 실제로는 "제대하는 꿈=재물·승진·합격 횡재"가 사전에 뚜렷이 있었다. **빈손 선언도 확인이 필요한 주장이다.**
   - **지배적 풀이를 반박하지 않는다.** 사전이 "애인이 군대 가는 꿈=떠남·이별 조짐"이라 하면, 그것을 "이별로 보기 어렵다"고 부정하는 대신 **전통을 인정하고 심리로 재해석하는 2층 구조**로 쓴다(불안 마케팅 금지와 양립한다). 부정하면 사실 오류가 된다.
   - **길흉이 갈리는 항목은 병기한다.** 한 사전 안에서도 갈래가 갈리는 경우가 많다(예: "다시 가는 꿈=발전 길몽" vs "재입대=스트레스"). 소수 갈래만 골라 단독 제시하지 않는다.

   **전통 근거층 점수를 세고 큐에 적는다.** 5갈래면 몇 갈래에 실제 사전 근거가 붙었는지(n/5). 기준선: accident 5/5, giving-birth 5/5, drinking 4/5, bath 3/5, **bird 초판 3/5(경계선)**, **military 초판 1/5(실패)**. 3/5 미만이면 발행하지 말고 주제를 바꾸거나 갈래를 재구성한다.

   **🛑 총점만 적지 말고 갈래별로 표를 적어라 (2026-08-11 신설).** `bird-dream` 초판이 큐에 **"전통 근거층 5/5"라고 썼는데 같은 줄에 나열한 근거 목록 7개 어디에도 5번 갈래("새 한 쌍")가 없었다.** 총점만 적으니 자기 목록에 반박당하는 거짓이 그대로 남았고, 적대적 재조사 전까지 아무도 못 봤다. 아래 형식으로 적는다.

   ```
   전통 근거층 4/5
   ① 까치=기쁜 소식·반가운 손님  (bigcity, daum, jjangguone 3곳)
   ② 비둘기=평화·화합, 관계 발전  (bigcity, daum 2곳)
   ③ 원앙 한 쌍=재결합 / 갈라짐=이별  (bigcity 1곳, 길흉 병기)
   ④ 품에 날아든 새=원하던 이성  (bigcity 1곳)
   ⑤ 새 한 쌍 나란히=?  ← 빈손. 사전 6곳·표제어 120건 전수 확인. 갈래 삭제
   ```

   **한 갈래가 두 장면을 묶고 있으면 각각에 근거를 붙여라.** bird 초판의 5번은 "쓰다듬기"(근거 1곳) + "새 한 쌍"(빈손)을 한 불릿에 묶어, **절반만 근거 있는 갈래가 온전한 것처럼 보였다.** 묶은 두 장면의 근거가 다르면 갈래를 쪼개거나 근거 없는 쪽을 뺀다.

   **갈래를 묶고 싶어지면 그것부터 의심하라.** 근거가 부족한 장면을 근거 있는 장면에 얹어 한 항목으로 만드는 것이 이 사이트에서 반복된 사고 형태다(driving 조수석, stairs 전 애인+계단, bird 새 한 쌍). 방증 신호: **`description`이나 `summary`를 쓸 때 그 갈래의 한쪽만 적게 된다면**, 스스로도 한 항목으로 요약이 안 된다는 뜻이다.

   **타깃 적합성도 함께 본다.** 사이트 타깃은 **연애 고민 20~30대 여성**이다. 갈래가 특정 성별·경험 전제(예: "전역한 지 오래됐는데" = 군필 남성)를 깔면 그 갈래에서 타깃이 통째로 튕겨 나간다. 위 사고에서는 정작 사전에 있던 "여자가 군대 가는 꿈=목표 달성·근심 해결"을 누락한 채 군필 전제 갈래를 제목의 절반에 올렸다.
3. **중복 회피** - `ls src/data/dreams/ | grep -v '^index.js$' | sed 's/\.js$//'`로 미발행 확인. **위 0번에서 원격까지 대조한 뒤에만 유효하다.**

## 4단계. 문장 규칙 (lovtaro 공통)

- **단정·예언 금지**: "반드시/100%/무조건" 금지. 꿈은 가능성의 언어.
- **불안 마케팅 금지**: "흉몽이니 조심" 식 공포 조장 금지. 부정적 통념도 "~불안이 비친 것"으로 심리적 재해석.

## 7단계. 파일 포맷

`src/data/dreams/{slug}.js` - 시드 3편과 **동일 스키마**(가이드와 같음):

```js
const SITE_URL = 'https://lovtaro.kr'
export default {
  slug: '...',            // 영소문자+하이픈, unique
  title: '...',
  category: 'person' | 'situation' | 'symbol',
  description: '...',
  createdAt: 'YYYY-MM-DD',
  updatedAt: 'YYYY-MM-DD',
  ogImage: `${SITE_URL}/og-image.png`,
  summary: '...',          // 한 줄 핵심 답(GEO 인용용). 제목 아래 박스로 노출. 단정 없이.
  sections: [{ heading: '...', content: `<p>...</p>` }],  // content는 신뢰된 정적 HTML
  faq: [{ question: '...', answer: '...' }],               // answer는 평문
  relatedReadings: [{ label: '...', path: '/reading/.../' }],
  relatedCards: [{ id: '...', name: '...' }],
  relatedDreams: [{ slug: '...', label: '...' }],          // 관련 꿈 내부링크(토픽 클러스터)
}
```
