# LOVTARO 주간 콘텐츠 생성

## 폴더 구조 (2026-07-20 확정)

```
content-output/{YYYY-MM-DD_day}/
├── insta/          인스타 (구 shortform / shortform-reel)
│   ├── scene01~0N.png    장면 이미지
│   ├── reel.mp4          릴스 영상 (scene 이미지를 이어붙인 것)
│   ├── copy.txt          인스타 전용 캡션 (아래 4섹션만)
│   └── reply_templates.txt  참여형만
├── youtube/        유튜브 쇼츠
│   ├── frames/           장면 PNG
│   ├── scenes.txt        장면별 길이 정의 (`파일명:초`)
│   ├── video.mp4         최종 영상
│   └── copy.txt          제목·설명·고정 댓글
├── carousel/       캐러셀 (토요일)
├── story.txt / story01.png   심리테스트 스토리 (평일)
└── twitter.txt     트위터 (날짜 폴더 최상위)
```

- **폴더명은 `insta`** — 구 `shortform`·`shortform-reel` 명칭 폐기
- **twitter.txt는 날짜 폴더 최상위** (story 파일들과 같은 위치)
- **틱톡 폐기 (2026-07-20)** — copy.txt에 틱톡 섹션 작성 안 함
- 유튜브는 인스타 자산 재활용 + 전용 장면 추가 (아래 "유튜브 쇼츠" 섹션)

## 실행 흐름

> **고정 순서 (2026-07-20 사용자 확정, 임의 변경 금지)**
> **① 현황 갱신(인사이트 스크린샷) → ② 날짜 질문 → ③ 훅 제시 후 승인 대기 → ④ "만들어" 지시 후 생성 → ⑤ 인스타 완성 → ⑥ 그다음 유튜브**
> 날짜를 먼저 묻지 말 것. 훅 승인 없이 파일 생성하지 말 것. 유튜브를 인스타보다 먼저 만들지 말 것(유튜브가 인스타 자산을 가져다 씀).

### 0. 현황 갱신 (가장 먼저)
- **⚠️ 실행 대장 먼저 Read: `.claude/insta-data/run_log.md`** — PC를 두 대 이상 쓰기 때문에 **다른 PC에서 이미 만든 주차를 또 만드는 사고**가 실제로 발생했다(2026-07-29). 시작 전 `git pull` 후 이 파일 + `git log --oneline -5 -- .claude/insta-data/`로 원격 대조할 것.
  - `content-output/` 폴더 유무는 근거가 안 된다 (gitignore라 PC 간 동기화 안 됨).
  - `~/skill-log.json`(PostToolUse 훅 자동 기록)도 근거가 안 된다. **홈 디렉토리라 PC 간 공유 안 됨 + 스킬 호출만 기록**해서 훅 승인 단계에서 중단해도 기록이 남는다.
  - **생성 여부의 유일한 크로스 PC 근거 = `run_log.md`.** 만들려는 날짜 범위가 이미 대장에 있으면 생성하지 말고 사용자에게 먼저 확인한다.

- **사용자 인사이트 스크린샷 확인 → 훅 메모리 갱신 (필수 선행 단계)**
  - 사용자가 직전 주 콘텐츠의 인스타 인사이트(조회수) 스크린샷을 첨부했으면 `.claude/insta-data/hook_history.md`의 해당 행 도달 수치를 즉시 갱신
  - 도달 등급 변동 시 🥇(1,000+) / 🥈(500-999) / 🥉(<500) 섹션 간 재배치
  - 스크린샷이 없으면 사용자에게 "직전 주 인사이트 스크린샷 있어?"라고 한 번 묻고 진행 (없으면 그대로 진행)
- **누적 데이터 위치 (2026-06-16 이전: 개인 메모리 → repo로 이전)**: `hook_history`·`card_usage`는 `.claude/insta-data/` (git 추적, PC 간 동기화됨). 시작 전 `git pull`로 최신 누적 확보, 생성 후 두 파일 갱신은 사용자가 commit하면 다른 PC에 반영됨. ⚠️ `content-output/`은 gitignore라 동기화 안 됨 - 누적 추적은 반드시 `.claude/insta-data/`에만.

### 1. 날짜 확인
현황 갱신을 마친 뒤 사용자에게 질문해라:
> 몇월 몇일(요일)부터 몇월 몇일(요일)까지 생성할까요?

사용자가 날짜를 알려주면 해당 기간의 콘텐츠를 생성한다.
폴더명은 `YYYY-MM-DD_day` 형식 (예: `2026-04-20_mon`).

### 1-1. 사전 확인 (날짜 확정 후)
- **`.claude/insta-data/run_log.md`에 그 날짜 범위가 이미 있는지 재확인** (0단계에서 읽었어도 확정된 날짜 기준으로 한 번 더). 있으면 중복이므로 생성 중단하고 사용자 확인.
- `content-output/` 기존 폴더 확인 (중복 방지). ⚠️ 큐 파일만 믿고 미발행이라 판단하지 말고 원격 대조할 것. 폴더가 **없어도** 다른 PC에서 만들었을 수 있으므로 `run_log.md`가 상위 근거다
- **⚠️ 미발행분 우선 소진 (필수)**: `run_log.md` 비고 + `hook_history.md`의 `미발행` 행·메모를 grep해 **아직 못 쓴 슬롯**이 있는지 확인. 있으면 **새 훅·카드를 짜기 전에 그 슬롯부터 다음 주 같은 요일에 재활용**한다(산출물은 `content-output/`에 이미 있음. 카드는 미발행이므로 사이클 미소진 = 재사용 가능).
  - 재활용 시 ① 사용 불가 사유를 사용자에게 먼저 확인(단순 미업로드면 재활용, 품질 문제면 재생성) ② 훅에 박힌 시점 문구("8월 첫 주말", "다음 주" 등)가 새 날짜와 안 맞으면 **해당 씬만 재생성** ③ 4주내 근접중복 재확인
  - **인스타 릴스가 미발행이면 같은 날 유튜브 쇼츠도 대개 함께 미발행**(카드·해석 등 소재를 공유). 재활용 시 `youtube/video.mp4`도 같이 넘길 것. 유튜브 결번은 8주 게이트 표본을 훼손하므로 `hook_history.md` 메모에 결번일을 누적 기록
  - 이력: 7/18 금·토 → 7/25 재발행 / 7/20 월 → 7/27 재활용 / 7/24 금 → 7/31 재활용 / 7/29 수 → 8/5 재활용(발행) / 7/31 금·8/1 토 → 8/7·8/8 재활용했으나 **또 미발행** / **8/7 금(펜타클7)·8/8 토(달·컵나이트·펜타클에이스) → 미소진(2026-08-09 기준 대기, 2주 연속 이월, 인스타+유튜브 동반)**
  - 🚨 **금·토 슬롯 3주 연속 결번**(누적 미발행 5건). 재활용 이월만 반복하지 말고 **다음 실행 시 원인(주말 업로드 시간 문제인지)부터 묻고**, 반복되면 금·토 편성 축소·예약 발행 전환을 제안할 것
- `public/images/cards-png/` 메이저 아르카나 목록 확인
- `public/images/mcards/` 마이너 아르카나 목록 확인
- **메모리 `.claude/insta-data/card_usage.md` 반드시 Read** — 누적 사용 카드 목록 확인 후 미사용 카드 풀에서 배정
- **갱신된 `.claude/insta-data/hook_history.md` 다시 Read** — 검증된 강한 훅(1,000회 이상) 변형 베이스로 활용 + 4주 내 동일·유사 훅 회피 + 약한 패턴 회피
- 최근 1~2주 콘텐츠에서 사용한 카드/훅 추가 확인 (중복 방지)
- **⚠️ 카드+패턴 조합 중복 체크 (필수, 단어 Jaccard로는 안 잡힘)**: 소개형 마이너 배정 시 그 카드가 **최근 8주 내 같은 패턴 태그**(특히 `반전행동`·`상대행동+내해석`)로 이미 쓰였는지 hook_history를 카드명으로 grep. 훅 문구가 완전히 달라도 **같은 카드 + 같은 반전 테마면 릴스 중복**으로 인지됨(예: 2026-07-01 완드나이트 "다가왔다 멀어지는" 훅이 #423 6/17과 문구만 다르고 카드·테마 동일 → 사후 적발·재생성). 겹치면 **다른 카드로 교체**하거나 **다른 패턴 축**(결정유보·권태·휴식·자기성찰 등 상대행동 아닌 축)으로 전환. hook_history 카드 태그가 비어 있으면(구포맷) 슬롯·훅 문구로 카드를 역추적해 먼저 태그를 채운 뒤 대조할 것.

### 2. 주간 전략 수립 + 훅 점검 (생성 전 필수 게이트)
아래를 정리해서 보여준다:
- 날짜별 포맷 배치 (insta 릴스/carousel) + 유튜브 쇼츠 유형(pick/single)
- shortform 유형 배치 (참여형/소개형 메이저/소개형 마이너) — 고정 주간 배치표 준수
- 날짜별 카드 배정 (메모리 `.claude/insta-data/card_usage.md` 기반 미사용 카드 우선)
- 날짜별 주제/훅 (메모리 `.claude/insta-data/hook_history.md` 기반 강한 패턴 변형 + 4주 내 중복 회피)

> ⚠️ **훅 점검 먼저 (2026-07-14 사용자 지시)**: **바로 파일 생성으로 넘어가지 말 것.** 위 배치와 함께 **날짜별 훅 문구 전체를 표로 제시**하고 다음을 자체 점검해 근거와 함께 보여준 뒤, 사용자 확인(또는 수정 지시)을 받고 나서 3단계 생성에 착수한다:
> - 각 훅이 hook_history의 검증된 강한 패턴(1,000+) 변형인지 / 약한 패턴 회피했는지
> - 4주 내 동일·유사 훅, 8주 내 같은 카드+같은 반전 테마 중복 없는지 (위 1단계 카드+패턴 조합 체크 결과 반영)
> - 8가지 훅 공식·훅 자체 체크 룰 5문항 통과 여부
> 사용자가 훅을 OK 하거나 **"만들어"라고 지시하면 그때 생성 시작**. (훅만 게이트 - 이후 이미지/카피 생성은 기존대로 승인 대기 없이 진행)

### 3. 파일 생성 순서
**인스타를 전부 끝낸 뒤 유튜브에 착수한다** (1~9 인스타 → 10 유튜브). 유튜브가 인스타에서 확정된 카드·훅·해석을 그대로 받아 쓰므로 순서를 뒤집으면 안 됨.
아래 순서로 **TodoWrite로 진행상황 추적하면서** 실행:

**[인스타 단계]**

1. 날짜별 폴더 구조 생성 (`{날짜}/insta/`, 토요일은 `{날짜}/carousel/`도)
2. 날짜별 `insta/copy.txt` 작성 (인스타 4섹션만)
3. 참여형이 있으면 `insta/reply_templates.txt` 작성
4. `{날짜}/twitter.txt` 작성 (날짜 폴더 최상위)
5. `scripts/templates/`에서 해당 포맷 템플릿을 `scripts/generate-{포맷}-{날짜}.mjs`로 **복사**한 뒤 카드/카피만 교체
6. 이미지 생성 스크립트 실행
7. **생성된 이미지 시각 검증 (필수)** — 각 장면을 Read 도구로 열어 다음 확인:
   - 한국어 렌더링 자소 정상 여부 (특히 `듦` 같은 겹받침 — KO_STACK 미적용 시 깨짐)
   - 텍스트 오버플로우/잘림 여부
   - 프레임·카드·텍스트 간격이 레퍼런스와 일치하는지
   - 코스믹 배경·달·별·프레임이 의도대로 그려졌는지
   - 문제 발견 시 스크립트 수정 후 재생성. 문제없어야 8번으로 진행
8. **심리테스트 스토리 5개 생성 (평일 월~금, 자동)** — `node scripts/generate-story-tests.mjs week <그 주 월요일 YYYY-MM-DD>` 실행. 5개 심리테스트를 월~금에 랜덤 배치해 각 날짜 폴더에 `story01.png` + `story.txt`(질문·링크URL·카드) 생성. 질문 중복은 `story_questions.md`, 카드 78장 no-dup 순환은 `story_cards.json`이 자동 관리. **생성 후 각 story01.png도 Read로 시각 검증** (자소/오버플로우). 상세는 아래 "심리테스트 스토리" 섹션 참고
9. **인스타 릴스 영상 생성** — `bash scripts/render-videos.sh insta {날짜들}` → 각 `insta/reel.mp4`

**[유튜브 단계]** — 위 9번까지 인스타가 완성된 뒤 착수

10. **유튜브 쇼츠 생성** — 아래 "유튜브 쇼츠" 섹션 절차대로 프레임 생성 → `bash scripts/render-videos.sh youtube {날짜들}` → 각 `youtube/video.mp4` + `youtube/copy.txt`. **인스타 훅을 복사하지 않는다**(2026-08-11 폐지, 아래 참조)

**[마무리]**

11. **`.claude/insta-data/card_usage.md` 메모리 업데이트** — 이번 주에 사용한 메이저/마이너 카드(커버+본문+참여 전부) 추가 기록
12. **`.claude/insta-data/hook_history.md` 메모리 업데이트** — 이번 주에 사용한 모든 훅 추가 기록 (훅 텍스트 + 슬롯 + 카드 + 날짜). 도달 수치는 "미기록"으로 두고 **다음 주 스킬 실행 시 사용자가 보여줄 인사이트로 갱신** (위 0단계 워크플로)
13. **⚠️ `.claude/insta-data/run_log.md` 실행 대장에 행 추가 (필수, 생략 금지)** — 형식 `| 주차(생성 범위) | 실행일 | PC | 생성 슬롯 | 영상 | 비고 |`. 이 파일이 **다른 PC에서 "이 주차 만들었나?"를 판단하는 유일한 근거**다. 부분 생성·중단도 그대로 적는다(비고에 명시).
14. **사용자에게 커밋 요청** — `.claude/insta-data/` 4개 파일(run_log·hook_history·card_usage·story_*)은 **커밋·푸시되어야 다른 PC에 반영**된다. 작업 완료 보고 시 아래를 함께 안내:
    ```bash
    cd ~/lovtaro && git add .claude/insta-data/ && git commit -m "insta {주차} 트래커" && git push
    ```
    커밋은 사용자가 직접 (git은 사용자 관리 영역). 안내를 빠뜨리면 다음 주 다른 PC에서 중복 생성 사고가 난다.

## 유튜브 쇼츠 (2026-07-20 신설, 매일 1개)

인스타와 **같은 소재를 유튜브 문법으로 재구성**한다. 인스타는 "훅 → 댓글로 답 제공"이지만 유튜브는 답글을 달지 않으므로 **해석을 영상 안에 전부 넣는다**(픽어카드 형식). 인스타 구조 그대로 올렸을 때 유튜브가 성장하지 않은 원인이 이것.

### 핵심 원칙

- **⚠️ 첫 장면 인스타 복사 규칙은 2026-08-11 폐지됐다.** 유튜브가 자기 훅을 직접 그린다. 복사가 필요했던 이유는 `youtube-shorts.mjs`가 카드 뒷면 색을 `SCHEME_KEYS[0..2]`로 하드코딩해 7일이 같아 보였기 때문인데, 그 줄을 날짜 시드 기반 `pickSchemesSeeded()`로 고쳐 우회책이 불필요해졌다. **다시 복사하면 요일별 배치가 통째로 덮여 날아간다**
- **요일별 훅 배치**(`HOOK_LAYOUT`): 월 가로일렬 · 화 부채꼴 · 수 카드앞면(텍스트 상단) · 목 대각선계단 · 금 카드앞면(텍스트 하단) · 토 겹친스프레드 · 일 삼각배치+Sunday 라벨. 텍스트 높이·달 위치(좌/우/없음)도 같이 갈린다. 날짜 접미사(`_mon`…)로 자동 분기하므로 `date` 필드만 맞으면 됨
  - 카드 뒷면 컬러가 매일 랜덤(`pickRandomSchemes`)이라 재활용해야 요일별 색이 달라짐. 새로 그리면 색이 고정돼 7일이 똑같아 보임 (2026-07-20 실제 발생)
  - 인스타 `scene02`(댓글 유도 CTA)는 **유튜브에 쓰지 않음** (답글 약속 문구라 부적합)
- **카드 이미지 원본 경로**: 메이저 `cards-png/{slug}.png`, 마이너 `mcards/{suit}/{Card Name}.png`
  - ⚠️ `cards-draw/`(560x840 압축본)·`cards-png/`의 일부 마이너(1200x630 OG 가로판)는 화질·구도 손실. 반드시 위 두 경로 사용
- **답글 약속 문구 금지**: "답글로 해석 드릴게요"는 인스타 전용

## copy.txt 구조

### 줄바꿈 보존 규칙 (전 플랫폼 공통, 필수)

인스타·유튜브는 캡션 붙여넣기 시 **빈 줄을 자동으로 제거**하기 때문에 사용자가 복붙하면 단락이 한 덩어리로 뭉친다. 이를 막으려면:

- **각 문장은 독립된 줄에 작성** (한 단락처럼 붙이지 말 것)
- **단락 사이 빈 줄은 반드시 `⠀`(U+2800, Braille Pattern Blank) 한 글자만 들어간 줄로 작성** — 시각적으로는 빈 줄로 보이지만 IG가 보존
- 일반 공백·탭·완전 공백 줄은 IG가 strip하므로 사용 금지

### 파일 포맷 규칙 (2026-05-16 확정, 엄수)

`copy.txt`·`twitter.txt`는 다음 4규칙 엄수:

1. **섹션 헤더 `[...]` 앞에 빈 줄 1개** (첫 섹션 제외) - 섹션 간 시각적 분리
2. **본문 단락 사이 `⠀` 사용** - 위의 줄바꿈 보존 규칙 적용
3. **CTA + URL + 해시태그는 글루** (캡션 마지막 블록, 사이에 `⠀`/빈줄 없이 연속 라인)
4. **짧은 CTA 섹션 내부 라인 글루** - `[인스타 첫 댓글]`, `[유튜브 고정 댓글]`의 2~3줄은 `⠀` 없이 붙여 작성

**Why**: Windows 메모장 복붙 사용성 + IG/유튜브 캡션 단락 보존 양립.

**좋은 예 (인스타 릴스 캡션)**:
```
지금 떠오르는 사람이 있다면
잠깐 멈추고 생각해보세요
⠀
1, 2, 3 중 마음 가는 번호를 골라보세요
고른 카드 기준으로 답글 달아드릴게요
⠀
✨ 매일 연애 타로 → @lovtarot_ 팔로우
⠀
#연애타로 #러브타로 #타로카드 #속마음타로 #짝사랑타로
```

**나쁜 예** (한 줄로 붙여넣기 + 일반 빈 줄):
```
지금 떠오르는 사람이 있다면 잠깐 멈추고 생각해보세요. 1, 2, 3 중 마음 가는 번호를 골라보세요.

#연애타로 #러브타로 ...
```

이 규칙은 **insta/·carousel/·youtube/ copy.txt의 모든 캡션 섹션**(`[인스타 릴스 캡션]`, `[인스타 캐러셀 캡션]`, `[인스타 첫 댓글]`, `[설명]`, `[고정 댓글]`)에 적용된다. `[제목]`·`[커버 문구]` 같은 단일 줄 항목은 예외.

## 이미지 생성 스크립트 규칙

- 파일명: `scripts/generate-{포맷}-{날짜폴더명}.mjs`
- Node.js + sharp 기반
- 실행: `node scripts/generate-{포맷}-{날짜폴더명}.mjs`
- `scripts/lib/card-back-svg.mjs` 사이트 정본 카드 뒷면 모듈 (변형 금지)
- `scripts/lib/color-card-back-svg.mjs` 참여형 전용 컬러 variant 카드 뒷면 모듈
  - `pickRandomSchemes(n)` — 7개 스킴 풀에서 n개 중복 없이 랜덤 픽
  - `getSchemeAccent(scheme)` — 번호 라벨 fill 색상 조회
  - `colorCardBackDefs()` / `colorCardBackSvg(cx, cy, scale, scheme)` — defs·카드 SVG 생성
  - 참여형 scene01에서만 사용. 소개형/캐러셀에는 정본(`card-back-svg.mjs`) 사용
- 스크립트 작성 후 반드시 실행하여 이미지 생성 확인
- 생성된 이미지를 Read로 확인하여 품질 점검
- `mulberry32` 시드 기반 `genStars` 함수로 별 생성 (별 배치가 실행마다 동일하게 재현)

### 레퍼런스 스크립트 (단일 소스 — `scripts/templates/`)

| 용도 | 템플릿 파일 | 비고 |
|---|---|---|
| 참여형 shortform | `scripts/templates/shortform-participation.mjs` | 2컷, 코스믹 |
| 소개형 마이너 shortform (기존 디자인) | `scripts/templates/shortform-minor.mjs` | 3컷, 확정안 |
| 소개형 메이저 shortform (NEW 디자인) | `scripts/templates/shortform-major.mjs` | 3컷, scene02는 마이너와 동일 프레임 레이아웃 |
| carousel (풀배경) | `scripts/templates/carousel.mjs` | 5장 |
| carousel 릴스 (하이브리드) | cover/closing은 코스믹 헬퍼, body는 `scripts/lib/carousel-shortform-template.mjs`의 `carouselShortformSlide()` | - |

- 새 스크립트 작성 = **템플릿 파일을 `scripts/generate-{포맷}-{YYYY-MM-DD_day}.mjs`로 복사 후 카드/카피만 교체**
- 템플릿 파일이 픽셀 수치·레이아웃의 **단일 소스**. 스킬 문서는 "디자인 의도"만 서술하고 수치는 템플릿을 따른다
- 수치 변경이 필요하면 **템플릿 자체를 업데이트** (스킬 문서 수치 수정만 하면 드리프트 발생)
- 코스믹 공통 헬퍼(cosmicDefs, cosmicBody, drawFrame, genStars, mulberry32)는 템플릿 안에 포함됨 — 그대로 재사용

**carousel 릴스의 scene02~04는 코스믹 헬퍼로 새로 그리지 말고 반드시 `carouselShortformSlide()`를 호출해 반환된 SVG를 그대로 sharp로 렌더링한다.**
