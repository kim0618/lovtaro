# 러브타로 가이드 작성 스킬 (프리미엄)

`lovtaro` 프로젝트의 `/guide` 섹션에 **퀄리티가 브랜드의 전부를 결정하는** 가이드 글 1편을 작성한다. 얇거나 AI스러운 글은 절대 발행하지 않는다. 한 편이 안 나오더라도, **기준 미달이면 기준까지 다시 쓴다**.

## 존재 이유

러브타로는 타로 서비스다. 독자는 "맞든 틀리든 해석이 마음에 닿는지"로 신뢰를 판단한다. 가이드 글은 그 신뢰의 첫 관문이다. 글 한 편이 얄팍하면:
- 검색 유입 독자가 3초 안에 이탈
- 브랜드 톤이 "그냥 그런 타로 블로그" 하나로 전락
- AdSense 심사 + E-E-A-T 평가에서 감점
- 리딩 서비스 신뢰도 동반 하락

그래서 이 스킬의 기본 자세는 **"검수자가 읽고 바로 발행 결재할 수 있는 수준"** 이다.

## 실행 일정

- **시작일**: 2026-04-19 (일) - Phase 2 Day 1
- **진행 속도**: **주 2편 - 월요일·목요일만** (2026-07-30 변경, 이전 "하루 1편" 폐기)
- **목적**: 네이버 SEO + 프리미엄 리딩 유입. (당초 목표였던 애드센스 신청은 2026-06-01 보류 확정 - CLAUDE.md 참조. 초기 누적 목표 35-49편은 이미 초과 달성, 엔진은 SEO·유입용으로 계속 가동)

### ⚠️ 주 2편(월·목) 전환 배경 (2026-07-30 결정)

하루 1편을 끊은 이유는 속도가 아니라 **연료 고갈과 그로 인한 품질 저하**다. 되돌리려면 아래 근거가 뒤집혔는지 먼저 확인할 것.

1. **수요 근거가 있는 레이어가 끝났다.** 카드 78장 가이드는 2026-07-19(page-of-pentacles)로 완주. 7/21 캡처에서 카드 가이드 갭 0 확인. 남은 백로그는 상황별 1개 + 방법론 7개 + FAQ 5개 = 13개인데, 카드 큐와 달리 항목별 노출 근거가 거의 없다(7/21 기준 근거 있는 건 "타로카드 78장 해석" 30위 하나).
2. **편당 수익률이 꿈해몽의 자릿수 아래다.** 7/21 웹문서 TOP30에서 가이드 레이어는 priestess-love 1개(234노출)뿐. 같은 캡처에서 꿈해몽은 old-friend 3062(전체 1위)·crush 2514·teeth-falling 1430 등 상위권을 도배. 편수는 가이드(90)가 꿈해몽(62)보다 많은데 성과는 반대.
3. **하루 1편 압박이 골격 복제를 만들었다.** 7/27 long-distance 발행당일 10건 수정, 7/29 infidelity 11건 수정 + relationship-rut과 N-gram 일치 29건(최장 26자, 같은 카테고리 정상 기준선 0~8건). 같은 날 bath-dream도 동일 원인. 78장을 다 쓴 뒤 상황별 글이 **이미 가이드가 있는 카드 6~7장을 다시 설명하는 구조**라 뼈대가 겹친다.

**남는 요일(화·수·금·토·일)은 신규 발행이 아니라 보강 슬롯이다.** 큐의 "🔁 기존 가이드 역방향 보강 대상"을 처리한다. 이미 색인·순위가 있는 페이지의 노출을 넓히는 작업이라 91번째 신규 1편보다 기대값이 높다.

**게이트: ~~2026-08-27 판정~~ → 2026-10-01 이후로 연기 (2026-08-04 변경).** 주 2편으로 4주 돌린 뒤 네이버 캡처로 가이드 레이어의 웹문서 TOP30 진입 수를 본다. 1개 → 3개 이상이면 주 2편 유지, 늘지 않으면 가이드 신규 발행을 동결하고 보강 + 꿈해몽만 남긴다.

### ⚠️ 게이트 연기 사유 (2026-08-04) - 판정 전 필독

**8/27 판정은 오염됐다. 그 날짜에 동결 결론을 내리지 말 것.** 게이트 직전에 구조적 SEO 변경 2건이 가이드 레이어에 들어갔다.

- **2026-08-03**: `/guide` 허브가 빈 `#app`이라 91편으로 가는 내부링크가 **한 줄도 없던 것**을 `buildGuideHubBodyHtml`로 주입(3.5KB → 43.8KB)
- **2026-08-04**: 가이드 상세 91편에 `relatedCards`·`relatedReadings` 링크가 **0/91**이었고, Vue 템플릿이 `href="#"`이라 JS 실행 크롤러조차 URL을 못 보던 것을 정정. 상세→허브·홈 복귀 링크도 0/156 → 156/156

즉 8/27까지의 데이터는 **"내부링크가 거의 없던 가이드 레이어"의 성적**이지, 고친 뒤의 성적이 아니다. 네이버가 156페이지를 재크롤·재색인·재평가하는 데 3.5주는 짧다.

**판정 규칙 (변경)**
- **날짜: 2026-10-01 이후**로 미룬다. 최소 8주 재크롤 창을 준다.
- **8/27에는 중간 관측만 기록한다.** 네이버 캡처를 받아 가이드 레이어 노출·진입 수를 큐의 갱신 이력에 적되, **판정하지 않는다.**
- **🛑 무결과를 동결 근거로 쓰지 말 것.** 10월 판정에서도 TOP30 진입이 3개 미만이면, 먼저 **색인·노출이 실제로 늘었는지**(선행지표)를 본다. 노출은 늘었는데 순위가 안 오른 것이면 "더 기다림", 노출조차 안 움직였으면 그때 동결을 검토한다.
- 이 기간에도 **억지 큐 정지선은 그대로 유효**하다(근거 없는 주제는 발행 금지). 발행 대상 6편은 8/20에 소진되므로, 8/20~10/01 구간은 자동으로 보강 슬롯이 된다.

**배경 교훈**: 고친 것 자체는 맞다. 게이트는 "가이드 콘텐츠에 수요가 있는가"를 물으려던 것인데, 크롤러가 내부링크를 하나도 못 보는 기술적 결함이 그 수요 측정을 이미 오염시키고 있었다. 안 고쳤으면 **핸디캡 걸린 레이어를 수요 부족으로 오판**했을 것이다. 잘못은 고친 게 아니라 **게이트 기준을 그대로 둔 채 고친 것**이었다.

## 편수 원칙 (절대)

- **월요일·목요일에만 1편.** 그 외 요일은 신규 발행하지 않는다.
- 사용자가 명시하지 않으면 **반드시 1편만**. 하루 2편 이상 작성 금지(Google 스팸 패턴 회피 + 한 편의 퀄리티 사수).
- **밀린 편수를 몰아 쓰지 않는다.** 월요일을 건너뛰었다고 목요일에 2편 쓰는 것 금지. 그 주는 1편으로 끝낸다.
- 기준 미달이면 2-3차 리라이트 허용. 편수 채우려고 얇은 채로 발행하지 않는다.

### 🛑 억지 큐 정지선 (2026-07-30 결정, 절대)

**주제가 억지스러워지는 지점에서 신규 발행을 멈춘다.** 요일이 월·목이어도, 큐에 항목이 남아 있어도 멈춘다. 78장을 완주한 뒤로 큐는 수요가 아니라 "빈칸 채우기"로 흐를 위험이 크다.

발행 직전 후보 주제에 대해 아래를 판정한다. **하나도 충족하지 않으면 억지 주제다.**

1. **네이버 캡처 근거** - 서치어드바이저 검색어·웹문서에 대응 노출이 잡힌다
2. **사이트 기능 대응** - `/reading/*` 8종, `/cards`, 프리미엄 리딩 등 실제 서비스 화면에서 독자가 부딪히는 선택·질문을 푼다
3. **독자 실질 질문** - 리딩을 반복 이용한 사람이 실제로 던지는 질문이다(예: 같은 카드가 계속 나오는 이유)

억지로 판정되면:
- 그 항목을 큐에서 **"보류(억지 판정)"로 옮기고 발행하지 않는다.** 억지로 각도를 발명해 쓰지 않는다
- 사용자에게 "남은 큐가 억지 구간에 들어갔다"고 보고하고, 해당 슬롯을 **보강 작업으로 대체**한다
- 보류 항목은 폐기가 아니다. 이후 네이버 캡처에서 근거가 잡히면 되살린다

**추가 금지**: 억지 판정을 피하려고 이미 발행한 글과 카드 구성·논지가 겹치는 주제를 "새 각도"로 포장하는 것. 7/28·7/29에 골격 복제로 실제 사고가 났다. 카드 6~7장이 기존 글과 4장 이상 겹치면 그 주제는 재서술이지 신규가 아니다.

## 0단계. 쓰기 전에 읽기 (Research Phase)

**이 단계를 건너뛰면 글은 반드시 얄팍해진다.** 자료 읽기를 충분히 한 뒤에만 써라.

### 0-0. ⚠️ 발행 요일 게이트 (가장 먼저, 생략 금지)

```bash
date +"%Y-%m-%d %u %A"   # 3번째 필드가 1(월) 또는 4(목)이어야 신규 발행
```

- **월(1)·목(4)이면** 그대로 아래 단계를 진행한다.
- **그 외 요일이면 글을 쓰지 않는다. 사용자가 이 스킬을 직접 실행했더라도 마찬가지다.** 사용자는 발행일을 기억하지 못한 채 습관적으로 실행할 수 있으므로, **조용히 진행하지 말고 반드시 먼저 알린다**:

  > 오늘은 {요일}입니다. 가이드는 2026-07-30 결정으로 **월·목 주 2편**만 발행하기로 했습니다(하루 1편 폐기). 오늘은 발행일이 아닙니다.
  > 대신 보강 슬롯 작업을 할 수 있습니다: {큐의 역방향 보강 대상 중 노출 큰 항목 1건 제시}.
  > 그래도 오늘 신규 1편을 쓰길 원하시면 말씀해 주세요.

  알린 뒤 사용자가 그래도 쓰라고 하면 쓴다(사용자 판단 우선). **알리지 않고 쓰는 것만 금지다.**
- 이번 주에 이미 2편(월·목) 발행했으면 사용자가 명시하지 않는 한 추가 발행하지 않는다. 확인:

```bash
git log --since="last monday" --diff-filter=A --name-only --pretty=format: -- src/data/guides/ | grep -v '^$' | sort -u
```

- **주 2편 체제 시작일: 2026-08-03(월).** 2026-07-30(목)~08-02(일)은 전환 공백으로 의도적 미발행이니, 이 구간에 발행 기록이 없는 것을 결번·누락으로 오판하지 말 것.

### 0-0b. ⚠️ 원격 동기화 확인 (생략 금지)

**큐 파일(`guides-queue.md`)만 보고 "미발행"을 판단하지 않는다.** 여러 PC에서 작업하므로 로컬 큐는 원격보다 뒤처져 있을 수 있고, 그 상태에서 미발행으로 판단하면 **이미 발행된 글을 중복 작성하게 된다.**

```bash
cd /home/tjd618/lovtaro && git fetch origin 2>&1 && git status -sb | head -3
```

- **원격에 새 커밋이 있으면(behind/diverged) 작업을 멈추고 사용자에게 pull을 먼저 요청한다.** 그 상태로 글을 쓰면 안 된다.
- 어떤 이유로 pull 전에 진행해야 한다면, 최소한 원격 큐와 원격 파일 목록을 직접 대조해 중복을 배제한다:

```bash
git show origin/main:.claude/guides-queue.md | grep -n "{후보 slug}"
git ls-tree origin/main src/data/guides/ --name-only | sed 's/.*\///; s/\.js$//' | sort
```

**배경 (2026-07-20 사고)**: 원격에 `page-of-pentacles-love-meaning`이 7/19 발행돼 있었는데 로컬 큐가 갱신 전이라 "미발행 마지막 1장"으로 보였고, git 확인 없이 같은 가이드를 통째로 다시 작성했다. 병합 시 add/add 충돌이 나 하루치 작업을 폐기했다. 원격 큐에는 `page-of-pentacles는 2026-07-19 발행`이라고 정확히 적혀 있었다.

## 1단계. 주제 선정

### ⚠️ 큐 소진 임박 체크 (주제 고르기 전에 먼저)

`guides-queue.md` 맨 위 "네이버 노출 역산 우선순위 큐"의 **미발행(`- [ ]`) 항목이 3개 이하로 남으면**, 주제를 고르기 전에 **작업을 멈추고 사용자에게 이렇게 요청한다**:

> "가이드 큐가 거의 소진됐어요. 네이버 노출 순으로 다음 큐를 재정렬하려면 **네이버 서치어드바이저 → 검색 키워드 TOP30 + 검색 웹문서 TOP30 화면**을 주세요."

받은 화면에서 노출 큰 **미발행 소드·완드·펜타클 카드** 순으로 다음 큐를 채운 뒤 발행을 이어간다. 네이버 노출은 GA4/구글 서치콘솔에 안 잡혀 자동 조회가 불가하므로 이 요청은 생략할 수 없다. (사용자가 화면을 못 줄 상황이면 백로그 풀 순서대로 진행하되, GA4 네이버 랜딩 페이지로 차선 정렬)

**큐를 재정렬했으면 `guides-queue.md`의 "📌 네이버 서치어드바이저 갱신 이력" 표 맨 위에 한 줄(갱신일·출처 캡처·큐 변경 요약)을 추가**한다. 덮어쓰지 말고 누적. 같은 네이버 캡처로 꿈해몽 큐도 함께 정렬했으면 그 사실도 같은 줄에 적는다.

## 2단계. 제목·메타 카피

### 제목 공식

구글 검색에서 **실제로 클릭을 받는** 제목을 쓴다. 너무 시적이면 CTR이 낮고, 너무 평범하면 AI스럽다.

**형식 A (카드 해석 글)** - `{카드 이름} {연애/타로} {핵심 키워드} - {부제}`
- 좋음: "달 카드 연애 해석 - 불안한 감정의 신호를 읽는 법"
- 좋음: "연인 카드 의미 - 진짜 선택이 다가왔다는 신호"
- 나쁨: "달 카드의 모든 것 완벽 정리" (AI 패턴)
- 나쁨: "달, 밤에 빛나는 이야기" (검색 키워드 부족)

**형식 B (상황 글)** - `{상황/질문} 타로 - {핵심 관점}`
- 좋음: "썸남 마음 보는 타로 - 연락 패턴에서 읽는 진심"
- 좋음: "재회 타로에서 자주 나오는 카드 조합 7가지"
- 나쁨: "썸남 마음이 궁금할 때" (타로 키워드 없음)

**형식 C (방법 글)** - `{방법} - {난이도/결과}`
- 좋음: "타로 3장 스프레드 해석법 - 과거·현재·미래 연결하는 법"
- 좋음: "역방향 타로 읽는 법 - 정반대가 아닌 이유"

### 길이 기준

- **title**: 25-40자 한국어 (Google 모바일 절삭 기준 안쪽)
- **description**: 70-120자. 글이 다루는 범위 + 독자가 얻는 것 + 자연스러운 호기심 유발
- **설명 금지어**: "완벽 가이드", "총정리", "한눈에", "모든 것"

## 4단계. 문장 쓰기 규칙 (핵심)

### 4-1. 목소리 (Voice)

- **페르소나**: 20-30대 여성 친구 중 가장 감정이 섬세하면서 타로를 잘 읽는 사람.
- **자세**: 관찰자. 판결자가 아님. 독자의 결정을 존중하되, 본 것을 선명하게 말해준다.
- **온도**: 따뜻하지만 호들갑 없음. 몽환적이되 흐리멍덩하지 않음.

### 4-2. 어미 가이드

- 기본: `~예요`, `~이에요` (부드러운 단정 회피)
- 중요한 정의·구조는 `~입니다` 한두 번만
- 금지: `~죠?`, `~잖아요`, `~거든요`, `~더라구요`, `~이시군요!`

### 4-3. 사례형 문단 필수

**모든 섹션에 최소 1개의 구체적 장면·사례가 있어야 한다.** 추상적 조언만 있으면 즉시 리라이트.

나쁨 (추상적):
> 달 카드는 관계에서 불안과 혼란을 나타냅니다. 감정의 파도가 느껴지며 확실하지 않은 상황이 이어질 수 있어요.

좋음 (구체 장면):
> 달 카드를 뽑았을 때 자주 보이는 풍경이 있어요. 연락은 끊기지 않았는데 대화가 얕아진다거나, 상대의 한 마디가 유독 오래 마음에 남는 시기. 달빛이 그렇듯, 보이는 것의 윤곽이 흐려지는 때예요.

### 4-4. 단정 금지

카드 해석은 가능성의 언어다. 결정론적 표현 일체 금지.

| 금지 | 대체 |
|------|------|
| 반드시 | 많은 경우, 대체로 |
| 100% | 뚜렷하게, 높은 확률로 |
| 절대 | ~하지 않는 편이 자연스러워요 |
| 무조건 | 대부분 |
| 보장됩니다 | 예상돼요 |
| 틀림없이 | 분명하게 느껴지기로는 |

### 4-5. AI 패턴 전면 금지

도입부 첫 문장에 다음이 나오면 **즉시 리라이트**:
- "안녕하세요", "반갑습니다"
- "오늘은 ~에 대해 알아보겠습니다"
- "이번 글에서는 ~을 정리해드립니다"
- "~에 대해 살펴보겠습니다"

글 어디에도 나오면 안 되는 것:
- "정리합니다", "완벽 가이드", "한눈에 정리", "총정리"
- "결론적으로" (굳이 말하지 않아도 됨)
- "~해드리겠습니다" (과한 겸양)
- "이시군요!", "그렇군요!" (AI 과잉 공감)

### 4-6. em dash(—) 전면 금지

전 프로젝트 공통 규칙. 필요 시 하이픈(-), 불필요하면 삭제. 쉼표·마침표로 대체 가능하면 그쪽 우선.

### 4-7. 자극·불안 마케팅 금지

- "이 사람과 헤어집니다", "큰일 나기 전에", "끔찍한 일이", "저주받은 관계"
- 타로를 통해 **공포를 팔지 않는다**. 러브타로 브랜드 톤 훼손.
- 역방향 카드 해석도 "잠시 돌아볼 때"로 열어둘 것.

### 4-8. 자가 부정 금지

"타로는 미신이지만", "재미로 보세요" 같은 표현은 본문에 넣지 않는다. 면책은 `/disclaimer` 페이지가 담당. 본문에서 자가 부정하면 브랜드 일관성 훼손.

### 4-9. 반복·중복 없는 문장

글 내에서 같은 의미의 문장이 두 번 나오면 하나 삭제. 카드 페이지(`cardDictionary.js`)의 `love` 문장과 **60% 이상 겹치는 문장** 금지 - 독자가 같은 글을 두 번 읽은 느낌을 가진다.

### 4-10. 구체성 점수

각 섹션을 쓴 뒤 자문: "이 문단에 **이 카드에만** 해당하는 구체적 디테일이 있나?"
- 있다면 OK
- "이 카드 저 카드 다 쓸 수 있는 문장뿐"이면 실패. 다시 쓴다.

## 5단계. FAQ 작성 (4-6개)

FAQ는 JSON-LD `FAQPage`로 들어가고 Google Rich Result에 노출된다. 퀄리티가 가장 눈에 띄는 파트.

### 질문 만드는 법

검색 쿼리를 상상한다. 독자가 실제로 구글에 치는 문장:

좋은 질문 예시:
